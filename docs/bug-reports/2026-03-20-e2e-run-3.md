## Observations

### OBS-1: Category varies between two scans of the same receipt — AI non-determinism (CLOSED)

**Severity:** Informational — not a bug

**What was observed:**
- `process_receipt` (T10) → `category: "Other"`
- `process_receipts_batch` (T13) → `category: "Meals & Entertainment"`
- Same file: `2026-03-18_WholeFoodsMarket_62.84.png`

**Root cause (confirmed via code inspection):**
Both tools use **identical code and the same API endpoint**. `process_receipts_batch` (`tools.py:366`) calls `self.process_receipt()` in a loop — the same method as the single-file tool. The full chain ends at `POST /receipts/scans` in both cases.

```
process_receipts_batch → self.process_receipt → api_client.process_receipt
  → scan_receipt → POST /receipts/scans   ← same endpoint, always
```

The category difference is **AI non-determinism**: two separate calls to the vision/LLM endpoint returned different categories for the same image. The pre-existing `vendor_contains: "Whole "` account rule is irrelevant — `process_receipt` writes to the local ledger only, never creates a server-side transaction, so account rules are never consulted.

**Status:** Closed. Expected probabilistic behavior from an LLM-based scan API.
